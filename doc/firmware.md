# Фърмуер — бележки и решения

> Документът се допълва с напредването на софтуерната разработка.
> Принцип: **само необходимото** — минимум зависимости и включени модули.

## 1. RGB светодиод WS2812

Вграденият светодиод на ESP32-S3-Zero (GPIO21) изисква драйвер за протокола WS2812
(времена ~0.3 / 0.9 µs, период 1.25 µs) — обикновено управление на GPIO не е достатъчно.
Референтните библиотеки `esp-led-status` и `outputwrite/led_indicator` управляват обикновен светодиод
(GPIO / LEDC) и не поддържат WS2812.

### 1.1 Избор на драйвер

| Вариант | Плюсове | Минуси |
|---|---|---|
| **`espressif/led_strip` (RMT бекенд)** ← *избор* | официален и поддържан от Espressif; проверени времена; малко API | външна зависимост (един компонент, без допълнителни зависимости) |
| Директно RMT + собствен енкодер | нулеви зависимости | собствен код за поддръжка (~80 реда) — дублира `led_strip` |
| SPI бекенд на `led_strip` | — | заема SPI контролер; излишно за 1 светодиод |

Неизползваният код (напр. SPI бекендът на `led_strip`) се отстранява от линкера (`--gc-sections`),
така че в изпълнимия файл влиза само RMT частта.

### 1.2 Минимална конфигурация

`main/idf_component.yml`:

```yaml
dependencies:
  espressif/led_strip: "^3.0.0"
```

Инициализация (1 светодиод, RMT, без DMA):

```c
#include "led_strip.h"

static led_strip_handle_t s_led;

void status_led_init(void)
{
    const led_strip_config_t strip_cfg = {
        .strip_gpio_num = 21,                 // вграден WS2812 на ESP32-S3-Zero
        .max_leds = 1,
        .led_model = LED_MODEL_WS2812,
        .color_component_format = LED_STRIP_COLOR_COMPONENT_FMT_GRB,
    };
    const led_strip_rmt_config_t rmt_cfg = {
        .clk_src = RMT_CLK_SRC_DEFAULT,
        .resolution_hz = 10 * 1000 * 1000,    // 10 MHz → стъпка 0.1 µs
        .mem_block_symbols = 0,               // 0 = минималният размер по подразбиране
        .flags.with_dma = false,              // DMA е излишна за 1 светодиод
    };
    ESP_ERROR_CHECK(led_strip_new_rmt_device(&strip_cfg, &rmt_cfg, &s_led));
    led_strip_clear(s_led);                   // изгасен при старт
}
```

Принципи за минимална употреба:
- Обновяване (`led_strip_set_pixel` + `led_strip_refresh`) **само при промяна** на цвета/състоянието,
  не в постоянен цикъл.
- Шаблоните (мигане, дишане) — с един `esp_timer`, без отделна FreeRTOS задача.
- Яркостта — мащабиране на R/G/B в нашия слой (един коефициент), не в драйвера.

### 1.3 Яркост

- Начална стойност: **20 – 30 %** (коефициент ~0.2 – 0.3 върху 0 – 255).
- Окончателната стойност се определя след проба на реалния хардуер в кутията.
- Предвижда се като настройка (константа / Kconfig, по-късно евентуално и в NVS).

### 1.4 Логика на индикацията

Цветове, шаблони и приоритети: [led-indication.md](led-indication.md).

### 1.5 Ресурси (RMT)

ESP32-S3 има 4 TX и 4 RX RMT канала. Светодиодът заема **1 TX канал**.
Ако за DS18B20 се ползва `espressif/onewire_bus` с RMT бекенд, всяка 1-Wire шина заема 1 TX + 1 RX канал:
2 датчика на отделни GPIO → 2 TX + 2 RX. Общо: **3 TX + 2 RX** — в рамките на наличните.

## 3. HomeKit — прозорец за сдвояване

Проверено в [esp-homekit-sdk](https://github.com/espressif/esp-homekit-sdk) (`components/homekit/esp_hap_core`):

| Елемент | Стойност / API | Бележка |
|---|---|---|
| Продължителност на прозореца | `HAP_PAIRING_MODE_TIMEOUT_IN_MINS = 10` (`src/esp_hap_pair_setup.c`) | по HAP Spec R16; вътрешен таймер `hap_pairing_mode_timer` |
| Таймерът се стартира | при старт без сдвоени контролери; при премахване на последния контролер; при всяко Pair Setup M1 (рестарт); при `hap_pair_setup_re_enable()` | вътрешни извиквания на `hap_start_pairing_mode_timer()` |
| Край на прозореца (изтекло време) | събитие `HAP_EVENT_PAIRING_MODE_TIMED_OUT` | SDK-то спира mDNS обявяването — аксесоарът вече не се вижда за сдвояване |
| Успешно сдвояване | събитие `HAP_EVENT_CTRL_PAIRED` | |
| Опит за сдвояване | `HAP_EVENT_PAIRING_STARTED` / `HAP_EVENT_PAIRING_ABORTED` | |
| Премахнат контролер | `HAP_EVENT_CTRL_UNPAIRED` (+ проверка `hap_get_paired_controller_count() == 0`) | прозорецът се отваря отново |
| Ново отваряне на прозореца | `hap_pair_setup_re_enable()` (публична функция в `hap.h`) | напр. от бутон, без рестарт |
| Брой сдвоени контролери | `hap_get_paired_controller_count()` | |

Няма публична функция „отворен ли е прозорецът“ — състоянието се поддържа във фърмуера от горните събития:

```c
static bool s_pair_window_open;

static void hap_event_handler(hap_event_t event, void *data)
{
    switch (event) {
    case HAP_EVENT_CTRL_PAIRED:
    case HAP_EVENT_PAIRING_MODE_TIMED_OUT:
        s_pair_window_open = false;           // спира дишането
        break;
    case HAP_EVENT_CTRL_UNPAIRED:
        if (hap_get_paired_controller_count() == 0) {
            s_pair_window_open = true;        // SDK-то стартира нов прозорец
        }
        break;
    default:
        break;
    }
    // → преизчисляване на индикацията и енергийния режим
}
// След hap_start(): s_pair_window_open = (hap_get_paired_controller_count() == 0);
// При hap_pair_setup_re_enable():  s_pair_window_open = true;
```

## 4. Енергиен режим на Wi-Fi

- Wi-Fi **не се изключва** — няма отделен режим за настройка с изключване на радиото.
- **Намалена мощност** се прилага само в един случай: прозорецът за сдвояване с HomeKit е изтекъл
  (`HAP_EVENT_PAIRING_MODE_TIMED_OUT`), **без да е имало опит за сдвояване** (не е получено `HAP_EVENT_PAIRING_STARTED`)
  и аксесоарът е останал несдвоен.
  - Мярка: по-ниска максимална мощност на предавателя — `esp_wifi_set_max_tx_power()` (стойността се уточнява на място;
    напр. от ~20 dBm към ~11 – 13 dBm).
  - Нормалната мощност се възстановява при ново отваряне на прозореца (`hap_pair_setup_re_enable()`) и при сдвояване.
- Ако устройството вече е било свързано и **връзката с Wi-Fi се загуби** — енергийният режим на чипа **не се променя**
  (само индикацията преминава в проблясък, а Wi-Fi стекът сам опитва повторно свързване).

## 5. Локално управление — дисплей и бутони

- Дисплей: TM1637, 2 цифри — собствена библиотека (ще се прегледа; клавиатурата на TM1637 не се използва).
- Бутони: 3 × GPIO с библиотеката `button` (кратко/дълго натискане, автоматично повторение).
- Обновяване на дисплея само при промяна на показваната стойност.

За уточняване:
- Какво се показва по подразбиране (напр. редуване T_COL / T_TANK, с отличителен знак за кой датчик е).
- Конвенция за ≥ 100 °C с 2 цифри (напр. „HI“, мигане, или стотиците като точка — „1.5“ = 150 °C).
- Меню и функции на бутоните (настройки на праговете, ръчно включване на помпата, режим Ваканция,
  ново отваряне на прозореца за сдвояване, фабрично нулиране).
- Показване на аварии на дисплея (напр. „E1“, „E2“, грешка на датчик „E3“/„E4“).
